Folentra Privacy Policy

Effective date: July 5, 2026
Last updated: July 20, 2026

Contact: support.folentra@gmail.com

Folentra is a personal-finance app for recording transactions, budgets, categories, tags, and local summaries. This policy describes Android package com.mojtaba.folentra.

Information stored locally

Transactions, amounts, currencies, dates, merchants, notes, budgets, categories, tags, and settings are stored in app-private storage. The Room ledger is protected by Android's app sandbox but is not encrypted by Folentra. Sensitive preferences such as App Lock state use encrypted Android shared preferences.

Financial data handling

The current app has no bank connection, server-backed account, cloud sync, import/export flow, advertising feature, or remote AI request path. Insights, search ranking, and autofill use on-device contracts or deterministic local fallback. App Lock limits casual UI access but does not encrypt ledger records.

Analytics and diagnostics

Firebase Analytics is included as a dependency. Release product-event behavior is no-op and feature code is not currently wired to send ledger events to Firebase. Google/Firebase SDK behavior may process technical app or device metadata. Folentra does not intentionally place exact amounts, balances, merchants, notes, search text, credentials, tokens, or raw ledger identifiers in analytics or logs.

Firebase configuration is injected only by protected release CI and is not stored in the source repository. Crashlytics is enabled only for configured release builds; debug and benchmark automatic collection remains disabled. Crash reports can include sanitized technical metadata and stack frames, but sensitive financial content must not be intentionally attached. Firebase App Distribution provides signed, minified release APKs only to authorized internal testers.

Permissions and third parties

AndroidX Biometric supports App Lock, WorkManager supports background work, Room stores local data, and AndroidX Security Crypto protects sensitive preferences. Firebase/Google dependencies can contribute internet, network-state, install-referrer, attribution, and advertising-ID permissions. The current release does not request contacts, camera, location, photos, calendar, SMS, phone, or microphone access.

Backup and device transfer

Folentra uses explicit deny-by-default Android rules. The ledger database and SQLite sidecars, encrypted preferences, app-private files, shared preferences, external files, device-protected storage, caches, logs, temporary/debug files, and generated reports are excluded from automatic cloud backup and device transfer. The backup-ready profile is a local foundation only; it does not upload, sync, or restore ledger data.

Sharing, retention, and deletion

Folentra does not sell personal data or send ledger records to a Folentra server. Records remain locally until deleted, app storage is cleared, or the app is uninstalled. There is no server deletion portal because no server-side account or ledger exists. Firebase/Google retention, when applicable, follows the configured service policies.

Security and children's privacy

No app can guarantee complete security. Folentra does not currently protect against compromised devices, screenshots, or screen recording. It is a personal-finance utility and is not designed for children.

Changes

This policy must be reviewed when analytics, crash reporting, accounts, cloud sync, backup, import/export, AI providers, permissions, or third-party services change.
