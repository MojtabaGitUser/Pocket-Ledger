چرا Repository؟ چه چیزی را در ViewModel نمی‌گذاری؟

سؤال شروع مصاحبه · ۳۰ دقیقه
Repository مرز میان منطق ارائه و زیرساخت داده است؛ ViewModel باید بداند کاربر چه عملی می‌خواهد، نه اینکه کدام جدول، DAO یا منبع داده آن را انجام می‌دهد.

در Repository قرار می‌گیرد

  • دسترسی به DAO، query و منبع داده
  • تبدیل Entity به مدل برنامه و سیاست cache
  • عملیات اتمیک، transaction و خطاهای ذخیره‌سازی

ViewModel روی این موارد تمرکز می‌کند

  • دریافت event و تولید UiState
  • مدیریت loading، error، lifecycle و cancellation
  • فراخوانی Repository یا Use Case و اعتبارسنجی فرم

مثال Folentra: ViewModel فقط confirmDraft(id) را صدا می‌زند؛ Repository تضمین می‌کند ثبت تراکنش و علامت‌گذاری draft در یک Room transaction و به‌صورت idempotent انجام شوند. Repository صرفاً wrapper روی DAO نیست؛ باید abstraction یا سیاست دادهٔ معناداری ایجاد کند.
